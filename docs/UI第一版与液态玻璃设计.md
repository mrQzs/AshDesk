# 极帧 AshDesk 第一版 UI 与跨平台液态玻璃设计

> 状态：设计稿 v0.1　｜　依据：[`UI设计.md`](UI设计.md)（下称“规范”）　｜　原型：[`design/prototype/`](../design/prototype/index.html)

本次交付是**可交互 HTML 设计原型 + Qt Widgets 落地方案**，不是已接入远程控制核心的 Qt 程序。交付目录为 `D:\Code\AetherDesk`；参考规范来自 `D:\Code\AshDesk\docs\UI设计.md`，已连同数学证明原样复制到本目录，便于离线查阅。用户选择的三平台 Qt Widgets 路线优先于原规范中的 Qt Quick / macOS 原生路线。

## 1. 目标与成功标准

| 目标 | 成功标准 |
|---|---|
| 第一版 UI（Q0） | 首页、会话、被控端、设备、设置五个界面信息架构完整；实色方案可独立落地，不依赖任何特效 |
| 液态玻璃（Q1–Q3） | 与第一版**共用同一套布局和控件**，玻璃只是材质层升级；任何时候可退回 Q0 而不改变布局和交互 |
| 跨平台 | Windows / macOS / Linux 共用一套 Qt Widgets 代码；平台差异只在窗口装饰、字体、快捷键 |
| 性能 | 目标是不为静态玻璃启动持续刷新；工具条收起时停用材质处理；视频链路增量必须实测，不能保证“零延迟”；预算按规范 §13 |
| 可访问性 | 减少透明度 → Q0；减少动态 → 无动画；高对比 → 强边界；所有图标按钮有可访问名称 |

## 3. ADR-001：三平台统一使用 Qt Widgets

- **状态**：已采纳（产品负责人决定：“macos不使用原生代码,直接Qt来实现,也不是用qt quick,使用widget”）
- **背景**：规范 §1.1/§2.3/§7/§11 原设计为 Windows/Linux 用 Qt Quick + 自定义 shader，macOS 用 SwiftUI/AppKit 原生材质。
- **决定**：UI 层三平台统一 Qt Widgets，不使用 Qt Quick/QML，不新增 SwiftUI/AppKit/Objective-C++ UI 分支。本文引用 Qt 6.10 API；实际实施时再锁定维护版本，不为原型引入 Qt 依赖。
- **规范中继续有效**：§4 组件语义与令牌、§4.5 可访问性、§8 几何与光学数学、§9 模糊成本、§10 局部更新与缓存、§13 质量分级与预算、§15 验证门禁。
- **规范中被替换**：§7 QML ShaderEffect 管线 → 本文 §7 的 Widgets 缓存绘制方案；§11 macOS 原生实现 → 与 Windows/Linux 同一路径。
- **边界**：仅设计共用 UI，不把现有 Windows D3D11 视频渲染器描述成跨平台实现。本次不修改它，也不引入原生玻璃、桌面捕获或窗口装饰库；真实视频接入属于后续独立实现与验收。
- **代价与风险**：
  - macOS 失去系统 Liquid Glass 材质与原生 toolbar/sheet 观感，由自绘材质近似；
  - Qt Widgets 没有 QML 场景图；默认采用应用自有背景的缓存绘制，不依赖抓取桌面或持续 CPU 回读视频；
  - 系统偏好只使用 Qt 公开能力；没有可靠跨平台 API 的选项提供应用内开关，不自行加入 macOS 原生探测代码。
- **回退**：任何平台出问题时整体退回 Q0（第一版），布局与交互不变。

## 6. 液态玻璃（Q1–Q3）

### 6.1 档位

| 档位 | 内容 | 用途 |
|---|---|---|
| Q0 | 实色 | 第一版；减少透明度；错误恢复 |
| Q1 | 模糊 + 饱和度，无折射 | 低功耗 / 大面积 |
| Q2 | 单 η 折射 + 边缘磨砂 | **默认** |
| Q3 | Q2 + 三通道色散（δ=0.01） | 有余量的设备 |

> Q3 色散按规范 §5.2 取 δ=0.01；这是折射率的艺术参数，不代表固定百分比的视觉提升。原型中“自动”固定使用 Q2，不模拟未实现的硬件探测。

### 6.2 光学（直接复用规范 §8）

圆角矩形 SDF → 斜面高度 `z = w(√(2t−t²+ε²) − ε)` → 法线 → Snell 折射 → 位移 `dp = h·T_xy / −T_z`（限幅 16 px）；磨砂权重 `smoothstep(0, 0.85, t)`，`body = mix(清晰折射, 模糊折射, 磨砂权重)`。默认 η=1/1.5、ε=0.08。

| 角色 | 斜面宽 | 基础厚度 h0 | 模糊 σ | 饱和度 | 底色不透明度（浅/深） |
|---|---|---|---|---|---|
| Navigation | 14 | 8 | 9 | 1.7 | .30 / .38 |
| Action | 12 | 7 | 7 | 1.7 | .40 / .46（视频上方 .58 / .50） |
| Popover | 10 | 5 | 14 | 1.35 | .72 / .80 |

高对比模式底色提到 .94 以上、去掉高光描边；降低透明度直接 Q0。

### 6.3 背景规则

- 主窗口玻璃**只浮在应用自绘的静态背景上**（渐变 + 与 Logo 同角度的斜向光带），不浮在滚动内容上。这让背景可缓存，是 Qt Widgets 下能做玻璃的前提。
- 玻璃内的子控件（分段、菜单项）用平面选中态，**不做玻璃套玻璃**。
- 被控端提示永远实色，不让对方桌面内容影响可读性。

## 7. Qt Widgets 实现方案

### 7.1 主窗口：CPU 缓存合成

```
静态背景 QImage（按 尺寸×DPR×主题 缓存）
  └─ 1/4 降采样 → 三次盒式模糊 → 饱和（ad_glass 内核）── 每次背景变化算一次，只存 1/4 大小
每个玻璃控件，形状变化时（尺寸×圆角×斜面×η×DPR×材质）：
  斜面像素表（16 B/像素，略过不折射、全磨砂且不透明的像素）+ 高光层 + 阴影
位置或背景版本变化时：
  双线性放大模糊背景填满玻璃体 → 斜面像素折射采样、按磨砂权重混合 → 叠高光 → 抗锯齿边补回阴影
  玻璃体与阴影共用一张预乘图
paintEvent 直接贴这张图；内容不变时不主动调度材质重算
```

- 像素热路径在 `core/kernels/ad_glass.*`：C17 整数定点，x86-64 用 SSE2（NASM）、AArch64 的 GCC/Clang 构建用 NEON，MSVC ARM64 / 无汇编构建退回 C 标量；行内核逐位一致，由 `test_glass` 对照。
- 窗口拖拽缩放：一串缩放的第一步完整重算（最大化、贴边结果立即正确），120 ms 内的后续步骤拉伸复用已缓存的背景和面板，停止后完整重算一次。
- 重算目标 p95 ≤ 2 ms（参考场景：地址框约 990×87 物理像素@1.5x）。实测见 §14，固定大面板 780×480 DIP@1.75x 合成 p95 约 3.58 / 5.25 ms，不能宣称所有面板已达到 2 ms；地址框参考场景尚未单独验收。空闲不重算，滚动和缩放时才触发。
- 背景版本、控件位置、主题、DPR、尺寸或光学参数变化时使相应缓存失效；悬停/按下只重绘前景层。缓存键包含背景采样位置，不能把移到不同背景位置的旧结果直接复用。

### 7.2 会话窗口：视频优先

| 路径 | 做法 | 状态 |
|---|---|---|
| **共用基线** | 工具条、HUD、浮层均为 Widgets；有可采样的应用自有背景时使用缓存材质。没有合适的视频表面接口时工具条使用实色，并保留全部操作；不逐帧 CPU 回读视频做模糊 | 默认设计，不增加平台原生 UI |
| **后续候选** | 在 Qt 管理的 Widget 视频表面中合成小面积玻璃 ROI，例如评估 `QRhiWidget`；必须验证纹理导入、控件叠放、DPR、焦点与输入法，以及使用 RHI 接口的版本约束 | 仅研究选项，未实现、未采纳为已验证路线 |

- 收起时停用工具条玻璃处理，只保留实色展开把手；不能因此直接推导端到端延迟“零增加”。Windows 现有 D3D11、macOS/Linux 视频接入分别验收，但不分叉 Widgets 控件代码。
- HUD 用高不透明深底，不做玻璃，保证数字可读。

### 7.3 窗口装饰与系统偏好

- 默认由 Qt 管理系统标题栏、拖拽、缩放和平台按钮；HTML 中的红绿灯等只是外观示意，不是系统窗口行为的实现。
- **qwindowkit**（Apache-2.0）仅作为无边框窗口的参考候选，本次不引入。它包含平台原生代码，不能默认为满足“不使用原生代码”的决定；若以后采用，须另行确认边界并验证系统窗口行为。
- 明暗：`QStyleHints::colorScheme()`；高对比：`QAccessibilityHints::contrastPreference()`（Qt 6.10）。
- 减少透明度/减少动态：三个平台均提供应用内开关；在已验证的 Qt 公共接口可用前，不增加手写平台探测分支。

### 7.4 控件映射

| 原型元素 | Qt Widgets |
|---|---|
| 导航按钮 | 可勾选 `QToolButton` + `setAccessibleName` |
| 地址框 | `QLineEdit` 嵌在玻璃 `QFrame` 中 |
| 分段控件 | `QButtonGroup` + 平面 `QToolButton` |
| 开关 | 自绘 `QAbstractButton` |
| 设置页 | `QStackedWidget` + `QFormLayout` |
| 浮层 / 菜单 | `Qt::Popup` 窗口 / `QMenu`（菜单用实色） |

## 8. 性能预算与验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 静态主窗口 | 0 次由玻璃主动调度的持续重绘 | 空闲 60 s，分别记录材质调度和系统暴露引起的 `paintEvent` |
| 主窗口玻璃重算 | p95 ≤ 2 ms（预算；固定大面板超出，地址框参考场景尚未单独验收，见 §14） | `QElapsedTimer` 包住重算，规范 §13.4 统计法 |
| 会话工具条 GPU（候选） | p95 ≤ min(1.5 ms, 0.15·Tframe) | 对实际后端异步采样；无可靠计时能力时明确报告不可用 |
| 会话 CPU 提交 | p95 ≤ 0.3 ms | `QElapsedTimer` 测量 UI 增量提交时间，GPU 执行另计 |
| 工具条收起 | 端到端延迟与无 UI 时无统计差异 | 现有延迟统计 + 规范 §13.3 场景 |
| 内存 | 报告背景与面板缓存实际占用 | `DesktopGlass` 打印清晰 + 模糊背景与各面板 `cacheBytes()` 之和 |

没有参考设备实测前，以上都是原型目标，不出具“达标”结论（规范 §13.2）。HTML 原型的耗时数字不能作为 Qt 性能依据。

## 9. 可访问性

- 所有纯图标按钮都有 `aria-label`（原型）/ `setAccessibleName`（Qt），提示文字取自同一名称。
- 精简可见文字但不删语义名称：例如密码显示为圆点，读屏读“一次性密码已隐藏”。
- 被控请求对话框默认焦点“拒绝”，Esc 等同拒绝；模态对话框限制 Tab 焦点范围，浮层打开时焦点进入、关闭时回到触发按钮。
- 小窗口与放大显示时重排工具条、设备权限和设置控件；不通过缩小字体隐藏操作。
- 连接进度用 `aria-current="step"` 标记当前步骤；倒计时数字不做实时播报。

## 12. 原型局限

- `backdrop-filter: url(#svg滤镜)` 目前只有 Chromium 渲染；其他浏览器自动停在 Q1。
- 原型的位移图在 JS 里逐像素生成，只用于看效果，与 Qt 实现性能无关。
- 远程画面、设备、链路统计、配对、唤醒均为本地演示数据，不发起真实连接或命令。文件传输、线路测试、系统快捷键和窗口按钮仅展示布局，不执行系统操作；表单值不持久化。
- 原型未实现多形状 smooth-min 融合、线性色彩管线、设备丢失恢复与真实质量自适应。它展示共享布局、单形状折射和回退策略，不宣称实现了参考规范的完整渲染器。

### 液态玻璃材质

`ui/liquid_glass.*` 是纯 Qt 的 CPU 渲染器，光学常数与 `design/prototype/glass.js` 一致（η = 1/1.5、斜面 ε = 0.08、最大位移 16 px、色散 ±1%、饱和 1.6、模糊 σ = 10）：

- `GlassSurface` 绘制并缓存窗口背景（渐变、色斑、24° 光带）及其 1/4 分辨率的三次盒式模糊、提饱和版本（只存 1/4 大小，合成时双线性放大），按尺寸 × DPR × 主题 × 材质失效。
- `GlassPanel` 按形状缓存斜面像素表、阴影和高光；按背景版本与面板位置合成玻璃体，与阴影共用一张图。悬停、按下、文字变化只重绘前景，不重算材质。
- 降采样、模糊、饱和、放大与斜面合成由 `core/kernels/ad_glass.*` 完成（C 标量 + SSE2 / NEON 汇编，见 §7.1）。
- 磨砂只模糊不折射；液态玻璃按斜面法线折射；色散对 R/B 通道使用不同折射率。
- 实色或系统高对比度时不建背景，面板释放全部缓存；令牌、焦点环（仅键盘导航显示）、SVG 箭头与禁用态图标在两种材质下共用。

实测（2026-11-10）：基线 `30f8938` 的渲染器 → 当前 C/汇编渲染器，均为 MSVC RelWithDebInfo、Qt 6.10.1、Fusion、offscreen、1120×740 DIP、DPR 1.75。每版先预热一次，再交替 AB / BA 跑 5 轮；两台机器使用相同 exe / DLL，SHA-256 已核对。以下是**各轮指标的中位数**，不是把不同轮次的样本混成一个 p95。虚拟机仍可能有其他负载，不宣称它处于受控空闲状态。

| 场景 | i7-12700K 本机 | Ryzen 9 9950X 虚拟机（.4） |
|---|---|---|
| 背景构建 | 23.06 → 13.83 ms（−40.0%） | 40.53 → 30.87 ms（−23.8%） |
| 清晰 + 模糊背景缓存 | 19829 → 10533 KiB（−46.9%） | 同左 |
| 当前全部面板缓存 | 21160 KiB | 21288 KiB |
| 空闲重绘 | 不重建背景、不重新合成面板 | 同左 |
| 已缓存整帧 p50 / p95 | 4.58 / 6.00 → 3.14 / 4.26 ms | 6.96 / 9.36 → 5.47 / 7.84 ms |
| 拖拽缩放每步 p95 | 11.65 → 9.95 ms | 22.39 → 16.09 ms |
| 滚动每步 p95 | 9.75 → 7.62 ms | 11.99 → 10.25 ms |
| **固定大面板合成 p95** | **4.64 → 3.58 ms**（−22.8%） | **8.31 → 5.25 ms**（−36.8%） |
| 640×480 玻璃整帧 p95（原场景测试） | 3.02 → 2.80 ms | **5.94 → 7.38 ms，未改善** |

内存数字是 `QImage::sizeInBytes()` 和面板缓存容器容量，**不是进程 RSS、峰值内存或 GPU 显存**。旧版没有面板缓存计数接口，因此不为该项编造前后对比。offscreen 计时不包括真实窗口合成器和屏幕显示，不能据此推导视频链路延迟。

`GlassBenchmark.FixedPanelMovement` 在同一个 780×480 DIP 的 Action 面板上只交替移动 1 DIP，先等待缩放计时器结束、预热 4 次，然后取 60 次合成；每步断言恰好合成一次，记录全部纳秒样本。当前 p95 在本机各轮为 3.27–3.80 ms，.4 为 4.35–5.51 ms。旧 `DesktopGlass` 的合成计时环混有不同尺寸和事件顺序，不再拿它代替固定负载结论；其原始结果仍完整保留。小窗口、虚拟机尾延迟和 2 ms 预算仍是限制，不能声称每个场景都加速。

Windows 真实平台后端另采集 18 张截图：6 张实色逐像素相同，玻璃各图 RGB 平均绝对差 0.61–1.22（0–255）。深色最大差 37；浅色全局最大差 255，36 个大差异像素对应旧版蓝通道回绕（例如 2 → 254），不是把这些像素排除后宣称“最大差 37”。坐标及前后值见 `visual-extreme-pixels.json`。公开的材质截图裁去了机器名和网络地址栏。

拖拽缩放中的过渡帧是缓存的拉伸，停止 120 ms 后恢复完整质量。DPR 1.75 等非整数缩放下 `QPainter` 走缩放绘制路径，尚未优化。macOS 与低端 GPU/CPU 未测；Linux 只在 WSL 与 qemu-aarch64 下跑过内核测试。

## 15. 配置恢复、地址簿、打包诊断与多语言

对应借鉴设计 L3、M1、A4、L5，均不引入新库。

- **配置带版本（L3）**：`desktop.ini` 写 `meta/version`（当前 2）。启动时 `prepareSettings()` 先检查：读不出来或版本比程序新，就改名为 `desktop.ini.bad-<时间>`、按默认值启动，并在底部状态栏说明备份位置；无版本号的旧文件照常读取，并把旧的 `connections/recent` 迁移到新格式。备份也失败时保留原文件、提示“修改设置会覆盖它”，不静默清空。主机设备表 `devices.dpapi` 同理：新文件头带版本，旧 `ADV1` 仍可读；读不出来（损坏、截断、换了 Windows 用户）时改名为 `.bad-<时间>` 留档并写日志，再按空表启动；版本更高的文件不动，主机拒绝启动。
- **地址簿（M1）**：最近连接可设别名与分组；右键或 F2 重命名、右键设置分组，列表显示别名（无别名时显示地址）、悬停显示地址，未分组在前、各组以粗体组名分隔。重新连接把条目移到最前，别名和分组保留；只自动淘汰第 12 条以后没有别名和分组的记录。在线状态依赖信令服务器，未做。
- **打包诊断（A4）**：设置 → 诊断 → 打包诊断，默认存到桌面。zip 内含版本与系统信息、两个日志窗口内容，以及核心目录（`core/`）、`%LOCALAPPDATA%\AshDesk`（`data/`）和它的 `logs` 子目录（`logs/`）中最新各 5 个 `*-crash-*.dmp`、`*.log` 和 `caps.json`；同一个目录不再以两个前缀各收一遍。文本只取末尾 2 MiB，并隐去 `--psk` / `--pair` 参数值、配对码和 32 位以上十六进制串；IPv4 / IPv6 地址换成只留类别的占位（`<ipv4-private>`、`<ipv6-loopback>` 等，类别为 loopback、link-local、private、public；`0.0.0.0` 和 `::` 原样保留，时间、版本号这类形似地址的文字不动）；`*.dpapi` 等密钥文件不收。界面拉起核心时带 `--log`，日志落在 `%LOCALAPPDATA%\AshDesk\logs\host.log` / `client.log`；核心是追加写，文件超过 4 MiB 时在下次拉起核心之前轮换成 `.1.log`，旧文件最多留 3 个。主机名、设备名不脱敏。只在本地生成，不上传。压缩用 Windows 10 1803 起自带的 `System32\tar.exe`（`--options hdrcharset=UTF-8`，否则中文文件名会乱码），不用 Qt 私有的 `QZipWriter`，也不手写 zip。小型转储含线程栈，可能留有会话临时密钥，无法事后清除，分享前需知悉。

`DesktopSettings`、`DesktopRecent`、`DesktopDiagnostics`、`DesktopLanguage` 四组 GoogleTest 用真实控件与真实文件覆盖以上行为；C 端设备表由 `test_devstore` 覆盖。

## 16. 状态回传、托盘、配对与设备权限、二次验证、网络诊断

对应借鉴设计 A2、M3、J1、J2、J3、B4 的界面一侧，不引入新库。界面和核心之间仍然只有继承来的 stdin / stdout，不开本地端口；命令和状态行的格式以 `docs/核心接口.md` 为准。

- **状态回传（A2）**：`CoreProcess` 把核心输出按行拆开，`@ui ` 开头的行解析成键值（`\s`、`\n`、`\\` 还原）作为 `message` 信号发出，不进日志框；其余照旧进日志框。一行状态或一个 UTF-8 字符被管道切成两段也能拼回来。会话页显示连接走到哪一步（查找主机 / 握手 / 协商 / 等首帧 / 已连接 · 直连、中转或 TCP 中转）、核心给的失败原因、每秒一行的帧率、码率、往返、丢包以及编码器和采集方式的名字；被控端页显示等待连接 / 正在连接 / 被控中（设备名、对端地址）、此刻有效的权限和同样的统计。原来“进程运行不代表连接已建立”“请查看诊断”两句提示已删除。失败原因是核心的原文，目前只有中文。
- **托盘（M3）**：主机核心在运行时才有托盘图标，此时关窗口是收进托盘；主机核心自己停了而窗口还收着时，窗口会自动回来，不留下没有入口的进程。图标是应用图标，被控时右下角叠一个琥珀色圆点（运行时用 `QPainter` 画在 16 / 20 / 24 / 32 px 的图标上，不增加图片资源）；提示文字是 `AshDesk · ` 加被控端页的状态。右键菜单：显示窗口、断开当前会话（发 `disconnect`，没有会话时禁用）、收回权限（子菜单列出这个会话开始时设备有的权限，取消勾选发 `perm -名字`，重新勾上发 `perm +名字`，勾选状态跟着核心每秒报的有效权限走）、退出（走原来的确认退出）。系统没有托盘时（`QSystemTrayIcon::isSystemTrayAvailable()` 为假）行为同以前。
- **二次验证（J1）**：设置 → 安全 → 二次验证可选关 / 配对时 / 配对和每次会话，对应主机的 `--totp pair|session`；“生成密钥”保留。选了却还没生成密钥时不拉起主机，直接提示。客户端被主机以 `error=5` 拒绝（退出码 3）时弹框输入 6–8 位验证码，带 `--totp` 重连；码不对再弹，取消就停在失败状态。
- **配对码与临时口令（J3）**：被控端页的“配对新设备”“临时口令”带着 `--pair` / `--pair-temp` 重启主机核心（正在被控时先确认，因为会把对方踢下线）。核心报来 `pair code=…` 后在状态下面用大号字显示配对码和剩余时间，`pair done` / `pair closed`、倒计时走完或主机停止时收起；配对码只来自状态行，不进日志框。
- **已配对设备（J2）**：设备页多一栏“已配对设备”（没有主机核心的安装里不出现），打开页面时用 `adrd_host --devices --ui-control` 取列表。每台显示名称、是否临时、配对日期、七项权限的勾选和“吊销”；勾选一动就按整排的状态调用 `--device-perm <ID> view|all|名字,…`，吊销先确认再调用 `--revoke <ID>`，跑完按设备表的实际内容重画，重画完之前这一栏不可点。权限勾选用折行布局（`FlowLayout`），640 px 宽的窗口里不出现水平滚动。原来那句“配对与权限管理尚未接入”已删除。
- **网络诊断（B4）**：设置 → 诊断里填信令服务器（可空，存进设置），点“开始诊断”跑 `adrd_host --netdiag [--rendezvous 主机:端口] --port N --ui-control`，按核心报来的顺序逐项填 NAT 类型、UDP 出站、TCP 出站、中转往返、端口映射，最后显示结论（核心没带说明文字时按 direct / relay / tcp / unknown 给一句界面自己的话；核心没给结论就退出则显示“诊断没有完成”）。“防火墙规则”一项由界面经系统的 `INetFwPolicy2` 接口自己查：规则组 `AshDesk` 里有一条已启用、放行入站、指向当前主机核心的规则才算已放行，不拉起 PowerShell。界面不带 `--port-map`：探测会在路由器上真的开一条映射，而界面拉起的主机并不使用端口映射，所以这一项如实显示“没测”。
- **端口转发入口**：设置 → 网络里的“主机允许转发到”“客户端端口转发”“客户端 SOCKS5 端口”对应 `--forward-allow`、`--forward`、`--socks5`，默认空 / 关 = 不带这些选项；写法由核心校验，写错时核心退出并在日志框里说明。仅传文件 / 仅端口转发的会话类型（`--session`）和 `--drop-dir` 没有做入口。
- **核心日志**：见 §15 的打包诊断一条。
- **多语言（L5）**：以上文字都在 `translations/ashdesk_en.ts` 里有译文。`DesktopLanguage` 的第二个用例在英文界面下把状态各阶段、托盘菜单、配对码、已配对设备、网络诊断各结论、二次验证对话框和确认框都走一遍，断言屏幕上没有中文，并在 640×480 下断言各页没有水平滚动。

测试用真实的 `MainWindow` / `CoreProcess`：状态行直接喂给 `CoreProcess::consume`；需要子进程行为的地方用假核心 `tests/gtest/fake_core.cpp`（几十行，只按约定打印状态行、回显收到的命令、记下每次调用的参数，不含业务逻辑），测试把它复制成 `adrd_host` / `adrd_client` 放进临时目录交给界面，数据目录也用临时目录，不碰用户的 `%LOCALAPPDATA%`。`DesktopCore` 另用真核心核对约定：主机报 `listening` 和临时口令、`--log` 落盘、空设备表的 `--devices --ui-control`，以及界面跑真核心的 `--netdiag`。设了 `ASHDESK_UI_SNAPSHOT_DIR` 时，这些用例把会话、被控端、设备、设置各页的新状态按浅色 / 深色各存一张，供 Windows 平台后端下的视觉验收。

未做或有出入：真实的配对加会话（需要一台对端）只由核心侧的回归覆盖，界面测试没有走；打包诊断的入口要过系统的保存文件对话框，文件夹清单的改动没有自动化用例；托盘图标的系统外观只做了启动确认，没有截图。

## 17. 驱动按需安装：界面一层

对应借鉴设计 §4.9（学“用到时再装”，不学“默认全装”）。安装脚本一层见 [安装与打包](安装与打包.md)：`install.ps1` 默认不装驱动，`-Drivers vdisplay,vaudio` 点名才装。这里补的是界面：功能真用到驱动、而驱动没装时，当场问用户要不要装。核心没有改，主机在 `--ui-control` 下本来就会报 `@ui need driver=vdisplay|vaudio`（`docs/核心接口.md`）。

- **入口**：设置 → 画质 →“主机使用虚拟屏”，默认关，存在 `host/virtualDisplay`（新增一个带默认值的键，配置版本没有升）。开了以后主机带 `--capture idd`。虚拟声卡没有开关：客户端真的发来麦克风声音、主机放不出来时核心才报。
- **流程**
  1. 核心报 `need driver=X`，界面弹确认框（安装 / 取消）。同一次主机运行里每个驱动只问一次（主机重试打开采集时会重复报）；界面不认识的驱动名不问。
  2. 取消：什么都不做。虚拟屏这条路上主机已经以非 0 退出，被控端页照常显示“核心异常退出”。
  3. 安装：在界面程序所在目录的上一级找 `install.ps1`（安装后的布局是 `<安装目录>\bin\ashdesk.exe` 和 `<安装目录>\install.ps1`）。找到就经 UAC 提权运行下面这条命令（`ShellExecuteExW` 的 `runas`），用 `QWinEventNotifier` 等进程退出，不阻塞界面线程，也不加轮询定时器：
     `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<安装目录>\install.ps1" -Destination "<安装目录>" -Drivers X -SkipOpenH264`
  4. 退出码 0：虚拟屏就把刚才失败的主机按原来的配对方式重新拉起；虚拟声卡提示“下次启动主机时生效”（主机只在启动时找一次虚拟声卡）。退出码非 0：状态栏给出退出码，并说明在管理员 PowerShell 里运行安装目录的 `install.ps1 -Drivers X` 能看到原因（提权出来的窗口跑完就关，报错留不住）。在 UAC 里点了“否”：提示“驱动安装没有启动”。
- **为什么带 `-Destination`**：脚本默认装到 `%ProgramFiles%\AshDesk`。装在别处的如果不带它，整个包会被再拷一份到默认目录，防火墙规则和卸载登记也跟着改到那边，所以命令里总是带上当前的安装目录。
- **没找到安装脚本**（从构建目录直接跑的界面）：不提权，状态栏提示在管理员 PowerShell 里运行安装包中的 `install.ps1 -Drivers X`。
- **装成功以后主机还报缺同一个驱动**：这次界面运行里不再问，状态栏提示去看被控端页的日志。已知会走到这里的情况：
  - 虚拟屏的控制接口只允许 SYSTEM 和 Administrators 打开（`proto/vdisplay/README.AshDesk.md` 的已知限制）。界面拉起的主机不提权，所以界面不是以管理员身份运行时，驱动装好了主机也打不开，报的仍然是 `need driver=vdisplay`——核心分不出“没装”和“没权限”。**也就是说，普通权限启动的界面现在用不了虚拟屏**，这一点要在核心或启动方式上解决，不是这次的范围。
  - 包里没有这个驱动，或虚拟声卡因为没开测试签名被跳过时，脚本只警告，退出码仍是 0。
- **代码**：`ui/driver_install.*`（找安装目录、拼命令是两个纯函数，提权启动单独一个函数）；`ui/main_window.cpp` 的 `offerDriver` / `installDriver` / `driverInstalled`。
- **测试**：`DesktopDrivers` 三个用例。
  - 开关能存取，开了主机参数带 `--capture idd`，关着不带。
  - 假核心带 `--capture idd` 时照真主机的样子报 `need driver=vdisplay` 并以 1 退出：界面询问；取消后同一次运行里再报不再问；再启动主机又问；点安装走到“没找到安装脚本”，状态栏里有 `install.ps1 -Drivers vdisplay`，主机没有被重新拉起。
  - 找安装目录（上一级有没有 `install.ps1`）和拼命令（带空格的路径加引号）。
  - `DesktopLanguage` 的第二个用例加了两句询问和“没找到安装脚本”的英文。
  - 测试里点“安装”之前先查界面找不找得到安装脚本，找得到就改成取消并报失败，所以测试不会提权。
- **没实测**
  - 真的提权安装这一整段没有跑过（开发机不装驱动）：UAC、真的 `install.ps1`、等退出码、装好后重启主机、失败 / 没有启动 / “装过仍然用不了”这几句提示。这几句提示的英文译文也因此没有被测试走到，只核对过 `.ts` 里没有待译条目。
  - 命令行的引号只这样核对过：用一个只打印自己参数的替身脚本，在**不提权**的 Windows PowerShell 5.1 下按同样的参数串运行，带空格的脚本路径和 `-Destination` 都原样收到，`-Drivers` 是一个元素的数组，脚本的退出码能传回来，脚本里 `throw` 时退出码是 1。

## 18. 号码连接：界面一层

对应 [号码连接设计](号码连接设计.md) 的 N3，细节和测试在那份文档的 §11。§4 信息架构里“本机 ID / 一次性密码”那一格到这里才是真的。

- **连接页**
  - “本机”一行：主机在跑并且登记了号码时，显示本机号码（一个按钮，点一下复制）和连接密码（默认遮成圆点；眼睛按钮显示，刷新按钮换一个）。主机没在跑、或者关了号码连接时，还是机器名和本机地址。
  - 点号码复制的是一句“号码 123 456 789，密码 1234 5678”（密码遮着也一样；主机没开连接密码时只有号码），提示写“复制号码和密码”。ToDesk、向日葵也是一下复制两样。
  - 地址框也认号码：只有数字、空格、连字符（全角数字当半角）的输入按号码认，不是 9 位就当场说明，不往下当地址连。
  - 地址框认对方发来的那一句：一共 17 位数字（前 9 位号码、后 8 位密码），夹着文字和标点都行，带着 `.` `:` `@` `/` 的不算。认出来就不再问密码，直接连；地址框里只留号码。密码不对时照旧带着原因弹密码框。
  - 按号码连先弹密码框，标题是对方的号码；8 位数字才能点“连接”。核心报密码不对（20）、对方换了密码（22）、连上后断了（25）时，带着核心给的原因再弹一次。
- **打开就上线**（2026-11-16）：“允许用本机号码连接”开着时，程序一打开就启动主机（`goOnline`），连接页马上有号码和密码，不用先去被控端页点“启动主机”。主机归系统服务管时接上服务的那个。主机在这个会话里采不到屏幕（远程桌面会话）会报 `@ui need screen=1` 后退出，状态栏说明原因。
- **被控端页**：“允许用本机号码连接”开关，存在 `host/number`，默认开；主机在跑时不能改。关掉以后打开程序不自动上线。
- **设置**
  - 网络 → 信令服务器（原来在“诊断”里，键还是 `network/rendezvous`）：留空用内置的那一台。
  - 安全 → 有人来连时：`security/confirm`，0 = 电脑前有人时询问（默认，对应主机的 `--takeover-confirm attended`），1 = 每次都询问（`always`）。
- **和核心的约定**（`docs/核心接口.md`）：主机报 `@ui number id=… [online=0|1]`、`@ui password code=…`；界面发 `password new`。装了系统服务时这些经服务的管道走，服务补发最近的号码和密码。
- **没登记上**：主机报 `online=0`（信令服务器连不上）时，号码变灰，提示和状态栏都写“没连上信令服务器，别人暂时用不了本机号码”；报 `online=1` 就恢复。
- **代码**：`ui/desktop_options.*` 的 `parseNumber` / `parseNumberTarget` / `parsePassword` / `groupDigits` / `signalServer` / `numberArguments` 和 `hostArguments` 的号码部分；`ui/main_window.cpp` 的 `connectToNumber` / `askPassword` / `showLocal` / `probeAddress`。
- **没做**：复制号码那一下（写系统剪贴板）没有自动化用例，测试不动用户的剪贴板——界面测试在 Windows 上跑的是真实平台插件。要复制的那句文字放在按钮的 `share` 属性里，测试查这个属性、再拿它喂给 `parseNumberTarget`。真的客户端按号码连只由核心侧的回归第 87、88 组覆盖。

## 19. 号码连接 N4：固定密码、记住设备的界面一层

对应 [号码连接设计](号码连接设计.md) 的 N4：§4.3 两种密码、§4.5 记住设备、§4.7 界面。命令和状态行以 `docs/核心接口.md` 为准。和前面两节不一样的地方：按号码连不再一上来就问密码（§18）；设备页“用 `adrd_host --devices` 取列表”（§16）现在只在主机没在跑时才这样。

- **按号码连**
  - 一个密码框认两种密码：8 位数字的临时密码（空格、连字符、全角数字照旧规整），或者对方设的固定密码（只去掉首尾空白，其余原样）。规则抄自核心的 `adp_password_kind`：8–64 个可打印 ASCII 字符，不以空格开头或结尾，不能只有数字、空格、连字符。“连接”按钮跟着亮灭；读屏名和占位文字是“对方的连接密码”。
  - 密码框默认遮着（2026-11-18 起，同连接页上本机的密码），右边一个“显示”按钮（眼睛图标，读屏名和提示都是“显示连接密码”）：按下露出来，再按遮回去；每次弹出来都是遮着的。遮着时复制、拖出照 `QLineEdit::Password` 的默认（不让），没有另加。对话框改成两列：密码框和“显示”占一行，原因和下面的按钮占满两列。这个按钮不走 `iconButton`：对话框用完就销毁，留在换主题时重画图标的那张表里会成野指针，所以按弹出时的配色画一次图标。
  - 密码不进命令行：有密码时参数是 `--connect 号码@服务器 --password -`，核心起来以后（`CoreProcess::launched`）界面往它的 stdin 写一行。
  - 只输了号码：先不带密码起一次。
    - 对方信任过这台设备：直接连上，不问。
    - 对方没记住这台设备：客户端先问一下信令服务对方在不在、收不收密码（在线查询，不叫醒对方；一般几十毫秒，信令服务不回话时问三次、一秒多），在报任何阶段之前就以退出码 3 结束：收密码、或者信令服务没回话，报 `error=30`；不在线 `error=26`；两种密码都没开（只接受记住的设备）`error=21`。（2026-11-18 起；之前是不联网、直接报 30。）
    - 30：弹密码框。`error=29`（对方不再信任这台设备）：带着核心给的原因弹。问到了再带着密码起一次，取消就停下。
    - 这段时间状态栏说“正在查找对方…”，人留在连接页上，“连接”按钮不可点；要密码就在原地弹密码框，会话页不会闪一下。这次试连在核心报出第一个阶段之前不切到会话页、不进“最近”；对方记得这台设备的，报出第一个阶段时切过去，状态栏那句收起来。
    - 26、21 这些问了密码也没用：不弹密码框，“正在查找对方…”收起，切到会话页，上面是“连接失败：”加核心给的原因。核心没起来、自己出错（什么都没报）也一样切过去，上面有退出码，不能停在连接页上什么都不说。
  - 贴进来的是“号码 + 密码”那一句：只起一次，带着密码（核心自己先试记住的密钥）。
  - 密码不对（20）、对方换了密码（22）、连上后断了（25）、格式不对（31）、对方没开这一种密码（32：关了临时密码、或者没设固定密码，另一种也许能用）带着核心给的原因再问；对方不在线（26）、两种密码都没开（21）、信令没回应（27）这些显示在会话页，不问。
  - 核心报 `@ui remembered=1`：状态栏“对方已信任这台设备，下次连接不用密码”；`=0`：密钥没存下来，下次还要密码。
- **信任这台设备**（被控端）
  - 主机的 `phase=stream` 行带 `trust=1`（这次是用密码连进来的临时设备）时，被控端页的状态下面和托盘菜单里各出现一个“信任这台设备”。行里是 `trust=0`、没有这一项、会话结束、主机停了，都收起。
  - 点了先确认（“以后它按号码连接本机不用输密码，可以在设备页吊销”），再发 `trust`。从托盘点的先把窗口叫回来，确认框才有看得见的父窗口。
  - 带设备号（2026-11-18）：`trust=1` 的 phase 行带着这台临时设备的设备号 `dev=`（32 个十六进制字符）。界面弹确认框之前记下这一刻的 `dev`，确认后发 `trust <dev>`，不再发不带参数的 `trust`。确认框转着自己的事件循环，开着的时候新的 phase 行照常进来；原来那台断开、换了一台用密码连进来时，发出去的还是确认的那一台，主机认出不是现在这台，回 `error=changed`，状态栏说“确认时的那台已经断开，换了别的设备连进来，没有信任新来的这台”。入口照最新的 phase 行：新来的这台也能信任，就还在。`trust=1` 却不带 `dev` 的（旧版主机，不认带设备号的 `trust`）不给入口。
  - `@ui trusted ok=1`：状态栏“已信任 名字”，设备页开着就重画。`ok=0`：按 `error` 的 none / changed / old-client / store 各说一句，不认识的原因也有一句。
- **固定密码**（设置 → 安全）
  - 一行里依次是：设没设（“已设置 / 未设置”，跟着 `@ui fixed set=` 走）、输入框（默认遮着，眼睛按钮显示）、“设置”、“清除”。四个控件都有读屏名；显示“设没设”的标签不另设名字，设了会盖掉它的文字。

  - `@ui device-perm ok=0` 不带原因：设备不在了、设备表存不下来分不开，界面只说“设备权限修改失败”。
  - 试连里报 27（信令没回应）的用例是假核心安排的。真客户端没被记住时，信令服务不回话报的是 30（让人照样能输密码）；被记住时 10 s 后报 27（见下一条）。界面对“问了密码也没用”的原因一视同仁，这一条验的是那一支。
  - 对方记得这台设备、可是信令服务一直不回话：做界面这一步时，真客户端停在“正在查找主机”一直查下去，不报 27。之后核心改了（11-18）：和带着密码的那条路一样，第一次连 10 s 后报 27，界面照常在会话页显示原因。回归第 90 组有一项查它。
  - 接着旧版主机（不报 `@ui temp` / `@ui fixed`）时，两个开关和固定密码那一行的提示说的是“这个主机没开连接密码”，其实是主机太旧。正常装出来界面和核心是同一版，不会这样。
  - “两种密码都关着”那句提醒只在界面自己改了设置、主机答成了以后说；主机启动时就是两种都关着，界面不说（连接页上没有密码）。
  - 真的主机加真的客户端走一遍“输密码连上 → 被控端点信任 → 断开再连不用密码”，界面这一层没有自动化用例（要两个核心加一台信令服务），这条路在核心侧的回归第 90 组里（`tools/run_proto_tests.sh`，做界面这一步时没有跑它）。
  - 做这一块时界面代理发现：主机一直把完整的临时密码写进日志，服务那份日志本机普通用户都读得到，“用过以后不换”又让它长期有效。核心已经改了（11-18）：日志里只记“换了新的”，码只经管道给界面。诊断包的脱敏没有加新规则：升级时主机重启，旧日志里的码随之作废；新日志里没有码。
