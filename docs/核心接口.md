# 界面和引擎之间的接口约定

AshDesk 的桌面界面（本仓库）不链接引擎的任何代码，只通过下面两种方式和它打交道：

1. 以子进程方式拉起引擎的 `adrd_host` / `adrd_client`，带上命令行参数（界面怎么拼参数见 `ui/desktop_options.cpp`），
   经继承来的 stdin / stdout 收发文本行（`--ui-control`）。
2. 装了系统服务时，连服务的命名管道，看、管服务拉起的主机。

引擎（AshDeskEngine）不开源，这份文档是它对外承诺的部分，摘自引擎里定义这两条管道的头文件的说明。
界面测试用的假核心（`tests/gtest/fake_core.cpp`）照这份约定实现，不需要引擎就能跑界面测试。

另外两个和引擎共用的名字：

- 系统服务默认叫 `AshDeskSvc`（`packaging/windows/install.ps1`、`uninstall.ps1`、更新器的 `--service` 默认值）。
- 主机在有客户端会话期间持有全局互斥量 `Global\AshDeskSessionActive`，更新器看到它就不在会话中途换版本。

## 1. 控制管道（`--ui-control`）

```text
adp_ui.h — 界面（ashdesk）以子进程方式拉起核心时的控制管道（--ui-control，借鉴设计 A2）。不开本地端口，只用继承来的 stdin / stdout。

界面 → 核心（stdin，每行一条命令）：
  stop                 正常收尾退出；父进程的管道断了等同 stop
  disconnect           主机：结束当前会话，接着等下一个
  perm -NAME / +NAME   主机：这个会话里收回 / 放开一项权限（NAME 同 adp_perm_parse 的单个名字）
  password new         主机：换一个连接密码（--password 开着才有用；新密码照常用 @ui password 报回来）
  password fixed 密码  主机：设固定密码（号码连接设计 §4.3；8–64 个可打印 ASCII 字符，不能只有数字、空格、连字符）。结果用 @ui fixed 报回来
  password fixed-clear 主机：清掉固定密码
  password temp on|off       主机：开 / 关临时密码（§4.3）。关了就不出码（@ui password code= 空着），8 位数字的密码连不进来
  password temp keep|rotate  主机：临时密码用过以后不换 / 用过就换（默认）。不换的也照样在连错 3 次、点了换一个、主机重启时换。
                       两条都存在主机上，主机重启照旧；结果用 @ui temp 报回来
  trust [设备号]       主机：信任正连着的这台设备——用密码连进来的临时设备转成长期设备，以后按号码连不用密码（§4.5）。结果用 @ui trusted 报回来。
                       界面带上确认时那一行 phase 的 dev=：会话中途换了人，主机就不信任新来的那台（error=changed）
  devices              主机：列出设备表，一台一行 @ui device，最后一行 @ui devices n=台数
  revoke 设备号前缀    主机：吊销一台设备（它正连着就断开）。结果用 @ui revoked 报回来
  device-perm 设备号前缀 权限   主机：改一台设备的权限（同 --device-perm 的写法），下次连接生效。结果用 @ui device-perm ok=0|1 报回来
  主机在跑的时候设备表归它管：界面的设备页要走上面三条，不要另起进程去改文件（那边不知道，下次存盘还会盖回去）
  客户端：--password - 时第一行是连接密码（不进命令行、不进日志），10 s 内要给

核心 → 界面（stdout，每行一条，以 "@ui " 开头，后面是空格分隔的 键=值）：
  @ui phase=NAME [键=值 …]        连接走到哪一步（只在变化时发）
  @ui error=CODE text=说明         明确的失败原因。CODE：1–5 主机拒绝（RDV_REJ_*），10 握手、11 解码器、12 呈现，
                                  20–32 连接密码（20 密码不对、21 对方两种密码都没开（只接受已记住的设备）、22 已换新密码、23 要等一会儿、
                                  24 没回应、25 密钥已失效、26 不在线或号码不对、27 信令没回应、28 验证出错、29 对方不再信任这台设备、
                                  30 要输入密码、31 密码的格式不对、32 对方没开这一种密码（临时 / 固定，另一种也许能用）、
                                  33 按地址直连时这个地址没有回应（CrossDesk 借鉴设计 CD10）；
                                  client_session.c 的 PWE_*）。20、22、25、29、30、31、32 时界面去问密码再连；21、26、33 不问。
                                  没给密码、对方也没记住这台设备时，客户端先问信令服务（不叫醒主机）：不在线 26，两种密码都没开 21，
                                  收密码 30；信令服务没回也报 30（带着密码的那次连接自己会试 TCP）
  @ui remembered=0|1              客户端：对方信任了这台设备，密钥存下来了没有（存下来以后按号码连不用密码）
  @ui phase=stream … trust=0|1 [dev=设备号]   主机：trust=1 = 这次是用密码连进来的临时设备，可以点“信任这台设备”（发 trust dev 的值），
                                  dev 是这台临时设备的设备号（32 个十六进制字符，只在 trust=1 时带）。信任以后这一行带着 trust=0 再发一遍
  @ui fixed set=0|1 [error=…]     主机：固定密码设没设。主机启动、设置、清除、换号以后各发一条。error：weak 不合要求、store 存不下来、
                                  off 主机没开连接密码、renumbered 本机换了号码，原来设的作废了
  @ui trusted ok=0|1 [name=… id=…] [error=none|changed|old-client|store]   主机：trust 的结果。none = 现在没有用密码连进来的会话；
                                  changed = 带来的设备号不是现在这一台（确认时的那台已经走了）；old-client = 对方的程序太旧，记不住密钥
  @ui device id=… name=… perms=… paired=Unix秒 temp=0|1 / @ui devices n=…   主机：devices 的答复（--devices --ui-control 也是这种行）
  @ui revoked ok=0|1 [id=…] [error=none|store]   主机：revoke 的结果
  @ui stats 键=值 …               推流期间每秒一行
  @ui pair code=… ttl=…           主机：正在配对，把码给界面显示
  @ui number id=… [online=0|1]    主机：本机号码（--number）；信令服务说号码已经归别的主机、本机换了号，再发一条。
                                  online：在信令服务上登记上没有（变了就再发一条；刚启动、还不知道时不带）。没登记上时别人找不到这台电脑
  @ui password code=…             主机：当前的临时密码（--password）；换了新的再发一条。临时密码关着时 code 是空的
  @ui temp on=0|1 keep=0|1 [error=off|store]   主机：临时密码开不开、用过以后换不换（keep=1 不换）。主机启动、改了设置以后各发一条。
                                  error：store 存不下来（设置没改，行里是原来的值）；off 主机没开连接密码（行里的两个值没有意义）
  主机的日志里不写临时密码、配对码本身：只经这条管道给界面（命令行起、不带 --ui-control 的主机打在标准输出上）
  @ui need driver=vdisplay|vaudio  主机：这个功能要的驱动没装（借鉴设计 §4.9：用到时再装），界面问用户要不要现在装
  @ui need admin=vdisplay          主机：驱动装了，但要管理员权限才用得了；界面提示，不问装不装
  @ui need screen=1                主机：这个会话里的屏幕采不到（桌面复制和 GDI 都不行，远程桌面会话里常见）。启动时碰到主机随后以 1 退出；
                                  界面说明本机为什么没上线
值里的空格写成 \s、换行写成 \n、反斜杠写成 \\（adp_ui_esc）。没调 adp_ui_enable 时 adp_ui_status 什么都不做。
```

## 2. 系统服务的管道

```text
adp_svc.h — 和 AshDesk 系统服务（adrd_svc）的命名管道对话，外加服务看门狗的熔断器（纯逻辑）。
协议：连 \\.\pipe\<服务名>，写一行命令（status / sas / restart-agent），读一行回复 "<码> <文字>"。
码与线上 AD_SAS_* 一一对应（0..5）；status / restart-agent 成功回 0（AD_SAS_NONE），不认识的命令回 4（AD_SAS_FAILED）。

界面管道 \\.\pipe\<服务名>.ui（借鉴设计 A2）：界面看、管服务拉起的主机。同一时刻只连一个界面，连着就一直开着。
  服务 → 界面：先一行 "@ui service agent=<代理进程号，0 = 没有>"，再补上代理最近的 phase、pair 行；之后代理每报一行 @ui
    （格式见 adp_ui.h）原样转一行。代理换了（退出、重拉、换会话）再发一次 service 行，界面据此清掉上一个代理的状态。
  界面 → 服务：disconnect、perm -名字、perm +名字，服务原样转给代理；别的（包括 stop）不转。
  界面 100 ms 内不读走、写不进去就被断开；控制台会话一变（可能换了用户）也断开，还有权限的界面自己重连。
两条管道的 DACL：SYSTEM 全权，Administrators 和控制台用户只有 FILE_GENERIC_READ | FILE_WRITE_DATA，
所以客户端要按这个权限打开（GENERIC_WRITE 多要了 FILE_APPEND_DATA，会被拒）。
界面管道另外放进别的登录会话里的管理员账户（adp_svc_admin_groups）：经远程桌面连着这台电脑的人在别的会话里，控制台上是
登录界面；开着 UAC 时他的界面拿的是过滤过的令牌，Administrators 那一条对它不起作用。普通用户的会话不放。
服务没在跑时别的账户能抢先建同名管道：界面打开后先看管道的属主，只认 SYSTEM、Administrators 和自己（ui/core_process.cpp）。
```
